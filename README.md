# 多色滚筒套准点校核 Web 应用

供印花车间校核 **2～8 个色筒（滚筒）标记点能否在同一匹布上同时对花** 的轻量 Web 工具。
输入各色筒的重复周长、标记偏移与布长，自动计算：

- **首次同时对花位置**（从布头 0 mm 起的最小非负解）；
- **共同重复周期**（各色筒周长的最小公倍数 LCM）；
- 无解时明确指出 **一对互不相容的色筒** 及判定依据；
- 无解时给出 **单色筒偏移修正建议**：逐个尝试只调整某一个色筒的偏移，
  按环形最短位移求出能使全组有解的新偏移（等距时取偏移增大方向），
  点击“采用”仅填入偏移并重新试算，保存仍由原按钮完成；
- **布长内最早的 20 个对花位置**（含距布头、剩余布长）与布长内对花点总数；
- **布面瑕疵避让**：每个方案可录入至多 20 个**禁印区间**（整数闭区间，
  端点同样不可使用），试算时先合并重叠或首尾相邻的区间，再从原对花序列中
  扣除落在区间内的点，返回**可用点总数、被排除点数与最早 20 个可用位置**；
  区间随方案保存，旧方案数据缺少该字段时自动视为空。
- **按序号定位可用对花点**：在结果区输入从 1 开始的十进制序号 N，直接返回
  扣除禁印区间后的**第 N 个可用位置、其在原对花序列中的序号 k 与距布尾余量**；
  服务端按可用前缀计数做边界定位，不按布长或前 N 个点逐一枚举，序号越界时
  给出明确提示。

技术栈：Node.js + Express + 原生 HTML/CSS/JavaScript（无前端构建步骤）。
方案持久化到本地 JSON 文件，所有整数运算基于 **BigInt**，输入与结果均不受
JavaScript 安全整数范围（2<sup>53</sup>−1）限制。

## 一、数学模型

色筒 *i* 的重复周长为 *p<sub>i</sub>*、标记偏移为 *a<sub>i</sub>*（`0 ≤ aᵢ < pᵢ`），
其标记在布面上出现的位置 *x* 满足同余式：

```
x ≡ a₁ (mod p₁)
x ≡ a₂ (mod p₂)
 …
x ≡ aₙ (mod pₙ)      （n = 2～8）
```

该方程组是**广义中国剩余定理（CRT）**：

- **有解** ⇔ 对任意一对色筒 *i, j*，`gcd(pᵢ, pⱼ)` 能整除 `(aᵢ − aⱼ)`。
  有解时所有解构成同余类 `x ≡ x₀ (mod L)`，其中：
  - `x₀` 为首次对花位置（最小非负解）；
  - `L = LCM(p₁,…,pₙ)` 为共同重复周期；
  - 之后的对花点为 `x = x₀ + k·L`（k = 0,1,2,…）。
- **无解** 时，必然存在至少一对色筒不满足上述相容条件，应用直接返回这对色筒、
  两者的 gcd 与偏移差作为证据。

布长内对花点按 **`0 ≤ x ≤ 布长`**（含布头 0 mm 与布长端点）枚举，
总数为 `floor((布长 − x₀)/L) + 1`，页面展示其中最早的 20 个。

### 布面瑕疵避让（禁印区间）

布匹上存在瑕疵时，可在方案中录入至多 **20 个**禁印区间 `[sᵢ, eᵢ]`，
要求起止均为十进制整数且 **`0 ≤ sᵢ ≤ eᵢ ≤ 布长`**，区间为闭区间，
**端点位置同样禁止使用**。试算时：

1. **合并**：先把互相重叠或首尾相邻（`s ≤ 前一终点 + 1`，整数位置之间
   已无空隙）的区间合并；
2. **扣除**：对每个合并区间 `[s, e]`，落在其中的对花点编号满足
   `s ≤ x₀ + k·L ≤ e`，即
   `ceil((s − x₀)/L) ≤ k ≤ floor((e − x₀)/L)`，被排除点数由上下界
   直接相减得到；合并后区间互不相邻，同一点不会被重复扣除；
3. 输出**可用点总数**（原总数 − 被排除点数）、**被排除点数**，以及按原
   对花序列顺序的**最早 20 个可用位置**（每个区间至多令游标按边界跳转
   一次）。

全部计数只依赖周期 `L` 与区间边界的 floor/ceil 除法，**不按布长逐点扫描，
也不按对花点总数枚举**，布长取 120 位大数时耗时与布长、对花点数量无关。
无解时不做避让，仍返回现有冲突证据与单色筒偏移修正建议。

### 按序号定位可用对花点

在“布长内、扣除禁印区间后的可用对花点序列”中定位第 N 个（N 为从 1 开始
的十进制序号）：

1. 与避让统计相同，先把重叠或首尾相邻的禁印区间合并（端点同样不可用），
   再把每个合并区间 `[s, e]` 换算为原对花序列的下标区间
   `ceil((s − x₀)/L) ≤ k ≤ floor((e − x₀)/L)`；合并后的区间互不相邻，
   这些下标区间也互不相交且按序排列；
2. 按下标区间顺序做 **BigInt 可用前缀计数**：若第 N 个可用点落在某段可用
   下标区间内，其下标 `k = N + 之前被禁用的下标总数 − 1`，位置
   `x = x₀ + k·L` 与**距布尾余量** `布长 − x` 直接算出；
3. N 大于可用点总数（或可用点为 0）时不定位，返回可用点总数与有效范围
   作为越界提示。

全程只对至多 20 个合并区间做 floor/ceil 除法与 BigInt 加减，**不按布长
逐点扫描，也不枚举前 N 个可用点**，N 取上百位大数同样即时返回。定位为
只读查询：不改变方案数据，也不影响“最早 20 个可用位置”的现有结果。

### 无解时的单色筒偏移修正建议

方案无解时，应用逐个尝试“只修改色筒 *k* 的偏移、其余色筒保持不动”：

- 若其余 *n*−1 个色筒的同余组 **自身已无解**，色筒 *k* 标记为“不可单独修复”；
- 否则其余色筒的解集为 `x ≡ A (mod M)`（*M* 为其余周长的 LCM）。新偏移 `a′`
  只需满足 `a′ ≡ A (mod g)`（`g = gcd(pₖ, M)`）即可使全组相容。
  调整量 `d = a′ − aₖ` 的候选构成公差为 *g* 的等差类，取其在 `(−g/2, g/2]`
  内的代表元即为 **环形最短位移**（等距 `2·|d| = g` 时取正值，即偏移增大方向）；
  新偏移为 `(aₖ + d) mod pₖ`。该代表元由取模直接得到，无需枚举候选，
  因此 120 位大数周长也能即时给出建议。

建议按 **|调整量| 升序**（相同则按色筒序号升序）列出，不可单独修复的色筒列于其后。

## 二、单条命令启动（Docker Compose，推荐）

前置条件：已安装 Docker 与 Docker Compose 插件。

```bash
docker compose up -d --build
```

启动后浏览器访问：

> **http://localhost:3000**

停止：

```bash
docker compose down
```

### 端口与配置

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 宿主机端口 | `3000` | 通过环境变量 `PORT` 修改，如 `PORT=8080 docker compose up -d --build` 后访问 http://localhost:8080 |
| 数据文件 | 容器内 `/app/data/schemes.json` | 挂载到宿主机 `./data/schemes.json`，容器删除/重建后方案不丢失 |

> 容器内应用固定监听 3000；`PORT` 只改变宿主机映射端口。

也可直接用 Docker：

```bash
docker build -t roller-registration .
docker run -d --name roller-registration -p 3000:3000 -v "$(pwd)/data:/app/data" roller-registration
```

## 四、页面使用说明

1. **左侧**为已保存方案列表，点击可载入；“＋ 新建”清空编辑器。
2. **右侧**填写方案名称、2～8 个色筒的重复周长与标记偏移（单位毫米）、布长。
   - 周长为正整数；偏移为非负整数且严格小于周长；布长为非负整数。
   - 可“＋ 添加色筒 / － 删除末个”，数量范围 2～8。
3. 需要避让布面瑕疵时，在“**布面瑕疵禁印区间**”区录入 0～20 个闭区间：
   - 起点、终点均为十进制整数，满足 `0 ≤ 起点 ≤ 终点 ≤ 布长`，**端点也不可使用**；
   - “＋ 添加区间 / － 删除末个”，每行还可单独点“删除”移除该区间；
   - 整行留空的区间不会提交；重叠或首尾相邻的区间由服务端自动合并。
4. 任意输入变化后页面**自动试算**（约 350 ms 防抖），也可点击“重新计算”。
5. 结果区显示首次对花位置、共同重复周期、**未避让前对花点总数 / 禁印区间
   排除点数 / 避让后可用点总数**（及合并后区间明细），以及最早 20 个
   **可用**位置（含其在原序列中的序号 k、距布头、剩余布长）；
   无解时显示一对互不相容色筒及 gcd/偏移差判据，并给出**单色筒偏移修正建议**
   （可修复色筒、原偏移、建议新偏移、有符号调整量）；点击建议行的“采用”
   仅把新偏移填入表单并重新试算，**不会自动保存**，需要保留时再点“保存方案”。
6. 结果区底部的“**按序号定位可用对花点**”输入从 1 开始的十进制序号，
   点击“定位”（或按回车）返回该序号的可用位置、原对花序列序号 k 与
   **距布尾余量**；序号超出可用点总数时给出明确提示（附有效范围）。
   方案无解或避让后可用点为 0 时该查询被禁用；定位为只读查询，
   不修改方案数据与上方结果。
7. “保存方案”保存当前输入（含禁印区间，更新正在编辑的方案），“另存为新方案”可复制变体；
   保存后仍可随时修改并再次保存。删除方案需确认。旧版本保存的方案没有禁印
   区间字段，载入时按空区间处理。
8. 超过 20 个可用对花点时，列表只展示最早 20 个，并提示可用点总数；
   其余可用点可改用“按序号定位”逐个查询。

**精度说明**：所有数字以十进制字符串收发并以 BigInt 计算，页面完整显示全部位数
（加千分位便于阅读），不存在科学计数法或尾数丢失。为防止资源滥用，
单个整数最多 **120 位十进制数字**（周长、偏移、布长均适用）。

## 五、HTTP API

基础路径 `http://localhost:3000`，请求/响应均为 JSON；大整数一律为**字符串**。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查，返回 `{"status":"ok"}` |
| `GET` | `/api/schemes` | 方案列表 |
| `GET` | `/api/schemes/:id` | 获取单个方案 |
| `POST` | `/api/solve` | 试算（不保存），返回对花结果 |
| `POST` | `/api/solve/locate` | 按序号定位第 N 个可用对花点（只读，不保存） |
| `POST` | `/api/schemes` | 新建方案 |
| `PUT` | `/api/schemes/:id` | 修改方案 |
| `DELETE` | `/api/schemes/:id` | 删除方案 |

请求体示例：

```json
{
  "name": "四色花型 A",
  "clothLength": "100000",
  "rollers": [
    { "perimeter": "640", "offset": "0" },
    { "perimeter": "800", "offset": "0" },
    { "perimeter": "900", "offset": "400" }
  ],
  "forbiddenRanges": [
    { "start": "1000", "end": "2600" },
    { "start": "30000", "end": "30500" }
  ]
}
```

`forbiddenRanges` 可省略或为空数组；至多 20 项，每项为
`{"start": "...", "end": "..."}`，要求 `0 ≤ start ≤ end ≤ clothLength`，
端点计入禁印。该字段随方案一并保存与返回（`GET /api/schemes`），
旧方案缺少该字段时视为 `[]`。

有解时 `POST /api/solve` 响应（`withinCloth.total` 为**避让后可用点总数**，
`originalTotal` 为扣除前点数，`excluded` 为被排除点数，
`mergedRanges` 为合并后的禁印区间，`positions` 为最早 20 个**可用**位置）：

```json
{
  "solvable": true,
  "firstPosition": "25600",
  "period": "28800",
  "clothLength": "100000",
  "forbiddenRanges": [
    { "start": "25600", "end": "25600" }
  ],
  "withinCloth": {
    "total": "2",
    "positions": ["54400", "83200"],
    "limit": 20,
    "excluded": "1",
    "originalTotal": "3",
    "mergedRanges": [
      { "start": "25600", "end": "25600" }
    ]
  }
}
```

无解时响应（`suggestions` 为单色筒偏移修正建议，按 |调整量| 及色筒序号排序，
不可单独修复的色筒列于其后；`adjustment` 为带符号十进制字符串）：

```json
{
  "solvable": false,
  "conflict": {
    "rollerA": 1,
    "rollerB": 2,
    "perimeterA": "6",
    "perimeterB": "4",
    "offsetA": "0",
    "offsetB": "3",
    "gcd": "2",
    "offsetDifference": "-3",
    "message": "色筒 1 与色筒 2 互不相容：gcd(6, 4) = 2 不能整除偏移差（0 − 3 = -3），两者的标记永远无法对齐。"
  },
  "suggestions": [
    {
      "roller": 1,
      "fixable": true,
      "perimeter": "6",
      "currentOffset": "0",
      "suggestedOffset": "1",
      "adjustment": "+1"
    },
    {
      "roller": 2,
      "fixable": true,
      "perimeter": "4",
      "currentOffset": "3",
      "suggestedOffset": "0",
      "adjustment": "+1"
    }
  ]
}
```

不可单独修复的色筒在 `suggestions` 中形如 `{"roller": 3, "fixable": false}`。

### 按序号定位：`POST /api/solve/locate`

访问地址 `http://localhost:3000/api/solve/locate`（端口默认 3000，可用
`PORT` 环境变量修改）。请求体在 `/api/solve` 的方案字段之外增加
**`index`**：从 1 开始的十进制序号字符串（不超过 121 位，前导零会被
规范化）。求解、禁印区间合并与端点不可用规则与 `/api/solve` 完全一致；
该接口为只读查询，不保存、不改变方案数据。

```json
{
  "clothLength": "100000",
  "rollers": [
    { "perimeter": "640", "offset": "0" },
    { "perimeter": "800", "offset": "0" },
    { "perimeter": "900", "offset": "400" }
  ],
  "forbiddenRanges": [{ "start": "25600", "end": "25600" }],
  "index": "2"
}
```

命中时响应（`position` 为距布头位置，`k` 为原对花序列序号，
`remaining` 为距布尾余量，`total` 为避让后可用点总数）：

```json
{
  "solvable": true,
  "found": true,
  "index": "2",
  "total": "2",
  "position": "83200",
  "k": "2",
  "remaining": "16800"
}
```

其他情形：

- **序号越界或可用点为 0**：`found: false`，附 `total` 与明确的中文
  `message`（含有效序号范围）；
- **方案无解**：`solvable: false` 与 `conflict` 冲突证据（形状同
  `/api/solve`，页面上此时禁用查询）；
- **序号缺失、非十进制整数、为 0 或超过 121 位**：HTTP 400 与错误信息。

## 七、常见问题

- **偏移量 0 是什么意思？** 表示该色筒的基准标记恰好在布头处（其标记点为周长的整数倍）。
- **为什么布长端点也可能出现对花点？** 应用按闭区间 `0 ≤ x ≤ 布长` 枚举；
  若布长恰好等于某个对花位置，该点计入（车间可据此判断末段是否还能对上一次花）。
- **禁印区间端点能用吗？** 不能。区间按整数闭区间 `[起点, 终点]` 处理，
  恰好在起点或终点上的对花点也会被扣除；两个区间若首尾相邻
  （如 `[1,3]` 与 `[4,5]` 之间没有整数空隙）会先自动合并，避免重复计数。
- **布长极大、对花点极多时会不会很慢？** 不会。避让统计只按周期和区间边界
  做 floor/ceil 除法，时间复杂度只与禁印区间数量（≤ 20）和返回条数（≤ 20）有关，
  不随布长或对花点总数增长。
- **按序号定位会随序号变大而变慢吗？** 不会。定位只对合并后的禁印区间
  （≤ 20 个）做可用前缀计数的边界换算，不枚举前 N 个点，序号取上百位
  大数也即时返回；序号为 0、非数字或超过可用点总数时会得到明确提示。
- **数据会发到外部吗？** 不会。所有计算在本应用进程内完成，方案只写入本地 JSON 文件。
